# Predictions for the evaluation scenarios

These predictions were written from the detection rules and their documented gaps alone, **written before any run of S06 to S29**. S01 to S05 carry the predictions they had before their first run. The first smoke run matched them. Nothing in this file is a result of a run, and no prediction was changed after a run.

Label set the predictions were written against (sha256 of the scenario files): `4dc82dc5803011cbe1724e41bb7edf12dad3603a8daee50041638eb7814b390c`

## Label principles

- Labels follow the attacker's goal and technique, not what the code is known to catch. A scenario that exercises a documented gap is still labeled expected for the detection designed to catch that behavior.
- Each expected and acceptable list is derived by reading the detection rules. An acceptable entry is a different detection whose alert on the same activity is reasonable by design, and it is used sparingly and justified in the notes of the scenario. Any alert from a detection that is in neither list counts as a false positive.
- Predictions come from the rules and the documented gaps only, never from a run result.
- The ordinary group was written by the same person who read the detection rules, so its recall is a best case and not a detection rate. The gap group is built to miss.
- Twenty-eight attack scenarios are a demonstration and not a statistical estimate.

## Predictions

predicted_outcome is detected (every expected entry met), missed (an expected entry not met), or no alerts (a benign scenario). Other alerts are detections expected to fire that are not in the expected list. The harness copies `predictions.json` into the results folder, records its sha256, and prints predicted against actual in the report.
